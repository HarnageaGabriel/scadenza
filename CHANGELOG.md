# Changelog

## Unreleased

### Highlights for 0.1.0

- **Inventory sources.** Certificate Transparency through Cert Spotter, with
  crt.sh as fallback; live TLS probes of named hosts; Kubernetes with
  cert-manager; and Azure Key Vault.
- **Correlation.** Certificates are matched by SHA-256 fingerprint, and each
  result states the correlation strength: `sha256`, `issuer_serial`,
  `names_and_expiry`, or `unresolved`.
- **Renewal classification.** Every certificate reports a mode (automatic,
  manual, unknown), health, the evidence behind it, the risks that break under
  shorter lifetimes, and the manual workload per owner at 200, 100, and 47 days.
- **Reliable results.** A `coverage` section, `--strict`, `--min-coverage`, and
  `--fail-on` keep an incomplete scan from looking clean; a dated CA/Browser
  Forum policy table and `--now` make results reproducible.
- **Safety defaults.** Kubernetes Secret data is read only with `--kube-secrets`,
  Key Vault certificates are read as public CER only, and diagnostics never carry
  credentials or raw API errors.
- **Distribution.** Linux, macOS (darwin), and Windows archives for amd64 and
  arm64, with checksums, a keyless cosign signature, an SBOM per archive, build
  provenance, and draft releases.

### Details

- Harden metadata-only Kubernetes mode: build the metadata client with only the `PartialObjectMetadataList` media types, reject any other successful JSON response without echoing its body so a server that ignores the request cannot return full Secret objects, and emit `SCD-0029` whenever Secret data reads are requested even when the Kubernetes client cannot be built.
- Add a release rehearsal workflow that runs GoReleaser in snapshot mode and checks the checksums, the six archives, one valid SPDX SBOM per archive, and the version reported by the Linux binary without publishing; fix the SBOM arguments so syft receives the `${artifact}` and `${document}` placeholders instead of unexpanded GoReleaser templates.
- Pin Go 1.26.9 in `go.mod` and run the vulnerability scan with the same toolchain the releases are built with, so `govulncheck` evaluates the shipped Go version.
- Isolate Azure Key Vault failures per vault: continue reading other vaults and report partial coverage when at least one succeeds, with `SCD-0030` for a rejected request (401), `SCD-0031` for a partial or list-time 403, `SCD-0032` for an unavailable vault, and `SCD-0033` for a skipped certificate.
- Fix the nightly fuzz workflow so its YAML is valid and it runs again, keeping target discovery and a two-minute run per discovered target.
- Add a read-only Azure Key Vault certificate source backed by the official Azure SDK `azcertificates` v1.5.0, with SHA-256 correlation, ownership tags, renewal evidence, safe diagnostics, and refreshed `scripts/third-party-licenses.sh` output for the new dependencies.
- Fix the M4b adversarial review: add the five renewal risk kinds and the new `renewal-config-invalid` to the published `findings.kind` enum and exercise every kind in the schema contract test; enforce cert-manager's own spec constraints (`spec.duration` greater than `spec.renewBefore` with equal rejected, a 1h `spec.duration` minimum, a 5m effective `spec.renewBefore` minimum, and `spec.renewBeforePercentage` computed from the actual issued lifetime) as the new `renewal-config-invalid` finding (`SCD-0028`, reported only, never on by default); apply the documented 90-day default when `spec.duration` is absent and record the evidence fact `duration-source=default`; pick the current and next CA/B step for renewal risks from `--now` instead of the policy computed from `notBefore`; bound the CT cadence window to a fixed `365*24h` ending at `--now` and ignore records issued after it; deduplicate CT records by stable issuance identity before computing cadence, so a precertificate and its final certificate and overlapping domain queries count once; normalize `renewal` configuration keys with the shared domain normalizer (lowercase, no leading wildcard, no trailing dot) and reject malformed keys; read `spec.renewBeforePercentage`; and label the announced Let's Encrypt lifetime steps as unconfirmed in risk details.
- Fix the M4a/M4b adversarial review: report unqueried fallback sources as `not requested`, track per-source partial failures, propagate `--now` into TLS and Kubernetes verification, add dated pre-2026 BR validity history, skip blocking non-compliance findings for already-expired certificates, reject empty `--fail-on`, resolve config-relative paths, preserve `SCD-0020` under higher exit precedence, strengthen `--min-coverage`, remove the dead backdate branch, key capped targets by host and port, and populate non-empty coverage details.
- Prepare 0.1.0 release machinery: draft GitHub Releases with checksums, keyless signing, provenance, nightly fuzzing, and DCO enforcement.
- Make Kubernetes Secret data access opt-in (ADR 0006 decision 8): `scan --kube` now uses `PartialObjectMetadata` for TLS Secret names, namespaces, labels, and annotations and builds fingerprintless observations from cert-manager Certificate status; `--kube-secrets` / `kube.secrets: true` enables `tls.crt` parsing and emits `SCD-0029`; unique exact name-set plus `notAfter` matches may correlate as `names_and_expiry`; the default RBAC manifest has no Secrets rule, with a separate opt-in manifest for cluster-wide or per-namespace Secret access.
- Add M4b renewal classification to `scadenza scan` (ADR 0006 decisions 5 and 6): every certificate carries `renewal` `{mode, health, evidence, risks}`, where `mode` is `automatic`, `manual`, or `unknown` and `health` is `healthy`, `degraded`, `configured`, or `unknown`, each with the evidence it is based on and `unknown` whenever evidence is missing; cert-manager `Certificate` resources (any managed issuer type, with health capped at `configured` for `external`/`unknown` issuers) and `cert-manager.io/certificate-name`-annotated TLS Secrets are `automatic`, CT/TLS-only certificates and unmanaged TLS Secrets are `unknown` (never `manual`), and `manual` requires an explicit `renewal: {"example.com": manual}` declaration in `scadenza.yaml`; Certificate Transparency cadence (`ct-issuances-365d`, `ct-median-interval-days`) is evidence only. New findings for configurations that break under shorter lifetimes: `renew-before-exceeds-lifetime`, `renew-before-loop-at-next-limit`, `duration-exceeds-next-limit`, `renewal-degraded`, and `manual-renewal-after-limit` (`SCD-0023`-`SCD-0027`), with `renew-before-exceeds-lifetime` and `renewal-degraded` on by default in `--fail-on`; a top-level `owners` summary of certificates, automatic/manual/unknown/degraded counts, and manual renewals per year at 200/100/47 days (`ceil(365/max_validity)`, unowned grouped as `(unowned)`); `--group-by owner|names|none` for table output only; `MODE`/`HEALTH` table columns and a `RISKS` summary; the new pure `internal/renewal` package (85 percent coverage floor); and additive `scadenza.scan/v1` schema fields. Adds `docs/renewal.md`.
- Add M4a reliable results to `scadenza scan` (ADR 0006): a `coverage` object (`targets_requested`, `targets_probed`, `targets_failed`, `names_not_checked`, per-source `sources` with `ok`/`partial`/`failed`/`not_requested`, and `ratio`) so a partial scan never looks clean, plus a one-line coverage summary in the table; `--strict` and `--min-coverage <0-100>` exit 5 (`SCD-0020`) for an incomplete scan; `--fail-on` selects which finding kinds cause exit 3, defaulting to `live_only,not-compliant-at-issuance` so `ct_only` (noisy on CDNs) and `exceeds-100d` (a readiness signal) are reported but do not fail by default; a dated `internal/policy` table (398 days before 2026-03-15, then 200/100/47 from 2026-03-15/2027-03-15/2029-03-15, SC-081v3) exposed per certificate as `policy` with `compliant_at_issuance`, `next_limit_days`, `next_limit_effective`, and `fits_next_limit`; `--now RFC3339` on `ct` and `scan` fixing the evaluation instant and `generated_at`; per-certificate `correlation_method` (`sha256`, `issuer_serial`, or `unresolved`, the weakest evidence); a strict `scadenza.yaml` via explicit `--config` (flags win, `SCD-0022`/`SCD-0021` on bad input); `not-compliant-at-issuance` findings; new diagnostics `SCD-0020`-`SCD-0022`; and JSON contract tests validating every scenario against `docs/schema/*.json`. Adds `docs/configuration.md`, `docs/adr/0007-json-compatibility.md`, and the documented exit precedence `2 > 4 > 3 > 5 > 0`.
