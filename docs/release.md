# Release runbook

## Before the first tag

- Run the release rehearsal workflow (`.github/workflows/release-rehearsal.yml`). It runs GoReleaser in
  snapshot mode with real SBOM generation and no signing on pull requests that touch the release files, and
  it can be started by hand. It does not exercise signing, attestation or the GitHub release.
- Confirm the CHANGELOG highlights for the release are accurate.
- Confirm `THIRD_PARTY_LICENSES/dependencies.csv` is current.
- Decide on Homebrew. It is not enabled because it needs the tap repository and a token, and krew is not
  planned for 0.1.0.

## What a real release run has proven

A throwaway release run on 2026-10-20 (tag `v0.0.0-rc.1`) proved the following.

- The release workflow runs on a pushed tag matching `v` followed by anything: `gates` (build, vet, race tests, cover floors) then `release` (GoReleaser, then build provenance attestation), ending in a draft GitHub Release.
- The draft holds six archives (`scadenza_VERSION_OS_ARCH.tar.gz`, `.zip` on windows, for amd64 and arm64), `checksums.txt`, `checksums.txt.bundle` and one SBOM per archive (`ARCHIVE.sbom.json`); VERSION has no leading `v`.
- The SBOMs are SPDX 2.3 JSON documents generated by syft that list the Go module dependencies.
- `cosign verify-blob --bundle checksums.txt.bundle` over `checksums.txt` verifies with the identity `https://github.com/HarnageaGabriel/scadenza/.github/workflows/release.yml@refs/tags/<tag>` and the issuer `https://token.actions.githubusercontent.com`; a wrong workflow name in the identity is rejected.
- `gh attestation verify <archive> --repo HarnageaGabriel/scadenza` verifies the provenance, and the attestation certificate names the same workflow and the tag ref.
- The binary built by the pipeline reports the tag version and the commit through the `version` command.

## Steps

1. Bump the version where the project defines it and update `CHANGELOG.md`.
2. Regenerate `THIRD_PARTY_LICENSES/dependencies.csv` with `scripts/third-party-licenses.sh` and commit it.
3. Run the CI gates locally: `go build ./...`, `go vet ./...`, `go test -race ./...`, and `make cover-floors`.
4. Create and push an annotated tag, for example `git tag -a v0.1.0 -m v0.1.0` and `git push origin v0.1.0`.
   Warning: a tag shaped like `v1.2.3` is protected by a repository ruleset, so it cannot be deleted, moved
   or updated once pushed, and a test tag with that shape stays forever. Rehearse with the rehearsal
   workflow instead of pushing a test tag.
5. Inspect the draft GitHub Release and its generated notes and assets, and
   run `scripts/verify-release.sh <tag> --gh-download` against the draft. The script automates the checks
   below, but it has not yet been run end to end against a real release.
6. Verify the checksum signature with `cosign verify-blob --bundle checksums.txt.bundle checksums.txt`, the
   certificate identity `https://github.com/HarnageaGabriel/scadenza/.github/workflows/release.yml@refs/tags/<tag>`
   and the OIDC issuer `https://token.actions.githubusercontent.com`. A wrong workflow name in the identity is
   rejected. `scripts/verify-release.sh` runs the same check.
7. Verify each artifact with `sha256sum --check checksums.txt` (or the platform equivalent).
8. Verify provenance with `gh attestation verify <artifact> --repo HarnageaGabriel/scadenza`, optionally
   adding `--signer-workflow HarnageaGabriel/scadenza/.github/workflows/release.yml`.
9. Publish the reviewed draft in GitHub Releases.
10. Post-release: install from the release, verify `scadenza --version`, check provenance and checksums again, and announce the release.

The Homebrew block is intentionally commented until the tap and token secret
are provisioned. Do not put tokens in this repository.
